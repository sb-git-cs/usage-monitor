## 3. Findings

| ID | Severity | Where | What happens to users | Fix |
| --- | --- | --- | --- | --- |
| A-01 | High | `src/updater.js:79-84` | "Yes" to an update runs `npm ci` inside the running app. `npm ci` deletes `node_modules`, which holds the running Electron binary. On Windows the locked files make it fail half-way, leaving a broken `node_modules`, so neither the relaunch nor the Startup shortcut can start the app. On macOS/Linux the delete succeeds, but Electron 44 only downloads its binary on the first `require("electron")` (`node_modules/electron/index.js`), so `app.relaunch()` points at a missing file and the app does not come back. It also runs even when dependencies did not change. | Fast-forward with git; only reinstall dependencies when `package.json` or `package-lock.json` changed, and do it from a detached script after the app exits, then restart through `scripts/start.js` (which downloads Electron). |
| A-02 | Medium | `src/updater.js:46-54`, `:81` | A clone without an upstream is compared with `origin/main`, but the update runs `git pull --ff-only`, which fails with "no tracking information". | Merge the exact ref that was checked (`git merge --ff-only <ref>`). |
| A-03 | Low | `src/updater.js:64` | Local commits that diverge from GitHub make `merge-base --is-ancestor` exit 1, reported as "Could not check for updates" plus a retry. | Treat divergence as "not updatable", say so on a manual check. |
| A-04 | Low | `src/updater.js:18-39` | `git fetch` can wait up to 45 s for a credential prompt nobody can see. | Run git with `GIT_TERMINAL_PROMPT=0`. |
| A-05 | Medium | `src/updater.js:86-89` | Relaunch uses `app.exit(0)`, which skips `before-quit`: pending config writes and up to 10 s of buffered network records are lost and SQLite is not closed. | Relaunch through `app.quit()` so shutdown runs. |
| A-06 | Gap | `src/updater.js:128-144`, `.github/workflows/release.yml`, `package.json` `build` | Installed builds (Windows installer, AppImage, dmg, portable, zip) never update; "Check for updates now" only offers to open the Releases page. Releases carry no update metadata (`latest.yml`), so no in-app updater could find them. | Add `electron-updater` for the Windows installer and the AppImage; publish `latest*.yml` and `.blockmap` files; for formats that cannot replace themselves (portable, zip, tar.gz, unsigned macOS) check the latest GitHub release and notify with a download link. |
| A-07 | Gap | `src/updater.js:96-125`, `src/main.js:775-785` | The startup check shows a modal Yes/No and runs once per launch. A laptop that sleeps and wakes with the app running is never checked again. | Install automatically (setting, on by default), check at launch, after resume from sleep and every 6 hours, retry with backoff when offline. |
| A-08 | High | `src/adapters/gemini.js:26-34`, `:111-130`, `:163-174`; `src/wincred.js` | On Windows Gemini is always treated as "credentials present". Whenever there is no valid cached token (not signed in to Gemini, or a token that cannot be refreshed) every poll spawns `powershell.exe` and compiles C# with `Add-Type` to read Credential Manager — every 5 s by default, forever. Constant CPU and battery drain on most Windows machines. | Cache the Credential Manager read (60 s after a hit, 5 min after a miss). |
| A-09 | Medium | `src/adapters/gemini.js:49-76` | To refresh a token the adapter reads the whole `agy` binary with `readFileSync` on the main thread. When no OAuth client is found the miss is not cached, so each poll reads it again (up to twice per poll), freezing chips, flyout and network window for the read. | Read asynchronously, cap the size, cache hits and misses by path + size + mtime. |
| A-10 | Medium | `src/main.js:1050-1057` | Only `display-metrics-changed` is handled, and only for docked widgets. Unplugging a monitor leaves floating chips/flyout at coordinates on the missing screen: invisible, while `isVisible()` still reports true, so the recovery timer does not help. | Re-place floating chips and a visible flyout on `display-removed`, `display-added` and metric changes. |
| A-11 | Medium | whole main process | No log file exists: `npm start`, the Startup VBS and packaged builds discard stdout/stderr, so update failures and crashes leave no trace (the README says logs live under the app folder). No `uncaughtException` / `unhandledRejection` handler: an uncaught error shows Electron's modal "A JavaScript error occurred" box. | Add a size-capped log file (`logs/main.log`) that receives console errors, update activity and crash handlers. |
| A-12 | Low | `src/alerts.js:75`, `src/poller.js:94` | Both caches are rewritten on every poll even when unchanged: about 34,000 file writes a day at 5 s. | Write only when the serialized content changed. |
| A-13 | Low | `src/net/index.js:493-505`, `src/ui/net.js:718-721` | A CSV export to a read-only or full location rejects the IPC call; the renderer has no `catch`, so nothing tells the user it failed. | Return `{ ok: false, error }` and show it. |
| A-14 | Low | `src/net/index.js:158-165`, `src/net/engine.js:206-209` | If saving records fails at runtime (disk full, records folder on a drive that was removed) the error only goes to the console; the window keeps showing numbers that are not being saved. | Show a banner warning while flushing fails; clear it on the next success. |
| A-15 | Info | `node_modules/electron/index.js` | Electron 44 downloads its ~100 MB binary lazily on first `require("electron")`. The first `npm test` after `npm ci` did the download inside a test run and reported 1 failure; 14 later runs passed 65/65. | Documented; the git updater now restarts through `scripts/start.js`, which triggers the download. |
| A-16 | Info | `docs/handoff.md`, README "Start at login" / "Use" / "Troubleshooting" | Docs describe a Yes/No update prompt and Git-only updates; handoff says Node 22.12 while `package.json` requires 22.13. | Update docs with the new behavior. |
| A-17 | Low | `src/net/store.js:268-271` | With reverse DNS on, each resolved address runs `UPDATE connections … WHERE remote = ?` with no index on `remote`: a full table scan per lookup on a large connection log. | Add index `connections_remote`. |

Reviewed with no finding: HTML escaping and CSP in all three windows, IPC argument validation (`src/main.js:895-974`, `src/net/index.js:522-551`), navigation/window-open denial, HTTP size and time limits (`src/http.js`), token refresh compare-and-swap (Claude, Grok), Windows helper pipe owner check (`NetCapture.cs:184`) and marker-scoped firewall rules (`setup.ps1`), config/cache corruption recovery, autostart quoting.
