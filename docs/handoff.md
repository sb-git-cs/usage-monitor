## Signed-in accounts (2026-09-30)

Settings, the flyout and the Android plans screen show the account each meter is reading. Switch account opens that tool's sign-in. A saved Grok sign-in can be selected without signing in again. A paired phone asks over `POST /v1/account/<tool>`, and the computer confirms before switching. Cursor and GitHub Copilot are metered when those logins are present (`cursor-agent login`, `gh auth login`). Pair a phone on the flyout or in Settings shows a QR code and a code immediately. Android widgets are listed at 4×2, 4×1, 2×1 and 1×1. The local checkout is `claude/beautiful-edison-ljkbkv` (1.3.0 plus this work).

## Direct phone reading and compact Home (2026-10-01)

The phone now reads accounts itself. **Link sign-ins** (Accounts) asks the computer, which confirms, to serve `GET /v1/tokens`: current access tokens only, never refresh tokens. The phone uses them while the computer's reading is not current. **Sign in** on the phone covers Claude Code (paste code), Codex and Grok (device code) and Cursor (browser approval); Gemini is link-only because its Google client secret is not sent to the phone. Source order and token lifetimes are in `docs/phone-accounts.md`; protocol in `docs/phone-protocol.md`. Home is one compact list, and widgets tag PC/Direct/Phone.

Verified: desktop `npm test` 124 pass; Android `testDebugUnitTest` 58 pass (25 usage-reader port, 13 direct-reading/merge/sign-in), lint 0 errors (14 pre-existing XML warnings). The optimized APK was installed on CPH2423 with `adb install -r` and kept pairing. Home and Accounts were inspected. Codex and Grok issued real device codes, then were cancelled.

Not yet verified: (1) **link end to end**, because the running desktop app predates `/v1/link`; restart the desktop from this tree, then Accounts → Link sign-ins → Allow; (2) **completing a phone sign-in** and its first usage read for each tool, which needs the owner's approval on each provider; (3) the Claude paste flow and Cursor's browser approval past opening the page.
